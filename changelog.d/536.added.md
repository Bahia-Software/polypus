`PauliSumOracle` (#531) now provides an exact parameter-shift gradient, so
Adam trains a Pauli-sum cost on an unbiased gradient instead of a finite
difference: when every parameter of the template is the angle `±θ + c` of
exactly one `rx`, `ry`, `rz`, `rxx`, `rzz`, `p`, `u1`, `u`, `u2` or `u3`
(`ParameterizedCircuit::check_single_frequency`, as Rotosolve requires),
component `k` is `[f(θ + π/2·e_k) − f(θ − π/2·e_k)] / 2`, measured with the
run's shots, and an Adam iteration is one batch of `2P + 1` candidates.
Otherwise the run falls back to finite differences as before,
`PauliSumOracleFactory::gradient_unavailable()` names the parameter and the
gate, and a warning is logged. ADR 0009 is amended (decision 8) (#536).
