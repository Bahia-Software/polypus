**BREAKING:** an explicit `seed` of `2**63` or more with `backend="aer"` or `infrastructure="cunqa"` now raises `polypus.ConfigurationError` (a `ValueError`) instead of reaching Qiskit Aer masked to 63 bits, which gave two seeds differing only in bit 63 the same counts; pass `seed & (2**63 - 1)` to replay a run made with such a seed. The native backend still takes any 64-bit seed. `polypus.torch.QuantumLayer(seed=...)` masks the seed it derives for each call to 63 bits, so a seeded layer gives the same values as before on Aer and CUNQA; on the native backend the calls whose derived seed had bit 63 set now sample differently (#393).
