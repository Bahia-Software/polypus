`PauliSumOracle` (#531) now runs a batch in windows of whole candidates,
sized by `candidate_window_size` as the QML oracle's are, so at most
`window × groups` bound circuits are alive at once however large the
population or the Hamiltonian; the expected values are unchanged, and a
seeded run on the native backend gives the same values bit for bit (a
backend seeded per call, such as Aer, now draws one stream per window). An empty batch no longer calls the planner, and a
group whose counts do not total the shots asked for (contract C-3), an empty
map included, is an `EvaluationError` naming the group and the candidate
under any planner, not only the built-in ones, which already reject such
counts; before, a planner of one's own could bias the energy silently.
`group_qubit_wise` leaves terms whose coefficient is exactly zero out of
every group, as it does identity terms, so they no longer cost circuits; a
Hamiltonian with nothing else to measure is
`PauliSumOracleError::NothingToMeasure` (#667).
