The native simulator now goes beyond 30 qubits where the memory budget
allows it (#428). Up to `polypus_sim::MAX_QUBITS` = 40, a known budget
(`POLYPUS_MEM_BUDGET`, or the RAM/cgroup limit detected on Linux)
decides: a statevector that fits runs, one that does not is refused with
`polypus.InsufficientMemoryError` before anything is allocated. Where no
memory limit is detected (macOS, Windows) statevectors still stop at 30
qubits with the same error as before, whose message now names
`POLYPUS_MEM_BUDGET` as the way to lift it. A direct `polypus-sim` caller
gets the new `SimError::AllocationFailed` instead of an abort when the
system refuses a statevector's memory. Calibration still reports `31` for
*never* (so caches keep their meaning), and the new
`CalibrationResult::parallel_threshold()` and
`CalibrationOutcome::parallel_threshold()` give the value to set as a
simulator's `parallel_threshold`, with *never* as `usize::MAX`, now that
31-qubit circuits exist.
