**BREAKING:** a seeded CUNQA run (`infrastructure="cunqa"`) gives different counts on QPUs 1 and up. QPU `k` of a call used to run with the call's seed `+ k`, so QPU `k` of seed `s` ran with the same seed as QPU `k - 1` of seed `s + 1`, and repetitions seeded `0, 1, 2, …` overlapped across QPUs. QPU 0 still runs with the call's seed (so a one-call run reports the seed QPU 0 ran with), and QPU `k >= 1` now runs with `stream_seed(stream_seed(c, 0), k)`, `c` the call's seed and `stream_seed` the SplitMix64 map the native backend also uses (the same function, not the same seeds), masked to the 63 bits Aer takes, so that QPUs no longer share seeds by construction, within a run or across its calls (short of a SplitMix64 collision, of chance about `2**-63`). The same seed still reproduces the same counts. For Rust and seam users: the CUNQA `run_qcs` call now carries `seeds`, one per circuit, instead of `seed` (contract C-1) (#635).
