An exact run on the native backend (`exact=True`) checked only its statevector against the memory budget, while it also held a vector of `2^n` probabilities and a map of up to `2^n` results per circuit: a dense 34-qubit run on a 512 GiB host passed the check and was then killed by the out-of-memory killer, with no Python exception. The probabilities vector is gone. `TrainedModel.run(exact=True)`, which returns those maps, now counts them against the budget beside the statevectors in flight: one that would not fit raises `polypus.InsufficientMemoryError` before it is allocated, after the run has dropped to one circuit at a time, while a sparse output stays cheap at any width; each map is freed as its Python dictionary is built, though those dictionaries (1.1 to 1.2 times the maps) are not counted. Exact training and gradients, `qml.expval`, `qml.jacobian`, `qml.vjp` and `TrainedModel.predict(exact=True)` build no map at all: they read each circuit's expectation values straight from its statevector, bit for bit what the map would give, so they need only the statevector budget, and the parameter-shift fallback of the exact gradient needs one statevector where the adjoint needs two. Under the fallback budget (no memory limit detected) nothing is refused, as before (#628).
